What this scanner does

For the chosen start token S, the scanner finds every pool S/Y across the enabled venues. It evaluates each two-pool cycle S → Y (buy pool) → S (sell pool) with exact integer (BigInt) AMM math. It reports the gross mid-price gap, the optimal input size and the profit at that size, and the result at your own size. Gas is not deducted, because it depends on your wallet and how you execute.

Data pipeline (as implemented)

  • Pool discovery: getPair (v2 factories) and getPool(a,b,fee) (LibertySwap V3 factory) for 7 pairs × 4 venues, all sent as one Multicall3 call.
  • State: getReserves for v2; slot0, liquidity and tickSpacing for v3. All are read in a single Multicall3.tryBlockAndAggregate (selector 0x399542e9) at 0xcA11…CA11, so every number comes from the same block. The block number is returned by the contract and shown in the telemetry strip. rpc.pulsechain.com rejects JSON-RPC batch requests, so Multicall3 is required, not optional.
  • RPC fallback: rpc.pulsechain.com, then pulsechain-rpc.publicnode.com.

Verified venue parameters

  • PulseX v1: factory 0x1715a3E4A142d8b698131108995174F37aEBA10D, fee 0.29%. Checked against router getAmountsOut, exact match.
  • PulseX v2: factory 0x29eA7545DEf87022BAdc76323F373EA1e707C523, fee 0.29%. Router match.
  • 9mm v2: factory 0x3a0Fa7884dD93f3cd234bBE2A0958Ef04b05E13b, fee 0.25%. Back-solved from on-chain Swap/Sync events; every sample was 25.00 bps.
  • LibertySwap V3: factory 0x796fcbDC956b85797EFe21145Aa97599B7FB36a6. Fee tiers 0.01 / 0.05 / 0.25 / 1%; tickSpacing is read on-chain per pool.

Math

  • v2: out = in·(1e6−fee)·rOut / (rIn·1e6 + in·(1e6−fee)), in integers (fee in ppm). The input size is capped at 10% of the input reserve.
  • v3: exact Uniswap-v3 swap math (full TickMath port, getAmount0Delta/getAmount1Delta rounding), multi-tick since v4.5: the swap walks up to N tickSpacing intervals per direction (adaptive since v4.8, cap 1–8 via the slider). Crossing a tick upward adds its liquidityNet; crossing downward subtracts it (uninitialized ticks have net 0). The fee is taken on the gross input. A swap that would go beyond the intervals read, or into a region with zero liquidity, is rejected, not approximated (flag “v3 multi-tick (≤N intervals)”). If the tick read fails, the scanner falls back to the old single-interval model (flag “v3 in-interval”).
  • Optimal size: binary search for the largest input that stays within both legs’ caps, then ternary search on the concave profit curve, then an exhaustive check of the final window.
  • USD values: WPLS/USD comes from the deepest v2 WPLS/USDC or WPLS/DAI pool, treating the bridged stables as $1. Other tokens are priced through their deepest WPLS pool.

LibertySwap bridge API (schema verified with live calls)

  • GET https://apis.libertyswap.finance/v3/swap/quote?srcToken&dstToken&amount(raw)&srcChain&dstChain&recipient. It returns srcAmount, destAmount, fee{protocol{percentage}, total{amount}}, approval, methodParameters{calldata,value}, route{type}. Errors come back as {"error": "…"}.
  • Observed routes: USDC 369→1 at 0.5%, WETH 369→1 (received as ETH) at 0.5%, USDC 1→369 at 0.3%. Same-chain swaps and PLS/pDAI cross-chain requests returned “Invalid quote request”.
  • /v3/swap/healthcheck returns 404, so health is taken from /v3/app/routers. The rate limit is 30 requests per 60 s; this page keeps 2 requests in reserve.

Corrections vs v4.1 / v4.2 draft

  • The PulseX v1 factory address had a typo (…f37eaba10d → …f37aeba10d), so v1 pools were never found.
  • The bridged USDC and DAI addresses were wrong. They have been replaced with the on-chain-verified 0x15D3…1F07 (6 dec) and 0xefD7…F305 (18 dec).
  • The 9mm fee was set to 0.30%; it is actually 0.25%. The PulseX fees were confirmed at 0.29%.
  • The old “Multicall” was a sequence of separate eth_calls, which could span blocks. It is now a real Multicall3 call at a single block.
  • The old cross-chain profit math mixed units. Bridge checks now compare USD values from an explicit reference price.
  • New: LibertySwap V3 on-chain pools are included in the cycle scan, and pools with a gap above 50% or a capacity below $25 are hidden as suspicious/dust by default.

Atomic execution: ArbExecutor (v4.6)

  • An open-source flash-swap contract (/contracts) executes a 2- or 3-hop cycle in one transaction. Leg A is a flash swap (tokens out first, repaid at the end), so no starting capital is needed.
  • If the cycle returns less than input + your min profit, it reverts with NoProfit; only gas is lost. Only the owner, or the keeper it appoints (v4.9), can call it; callbacks are accepted only from the pool currently being swapped.
  • Supported pools (callbacks verified on-chain): PulseX v1/v2 (uniswapV2Call), 9mm v2 (pancakeCall), LibertySwap V3 (libertyV3SwapCallback). Fee-on-transfer tokens are not supported.
  • In Trade Companion, enter your deployed address, then Build calldata and Dry run. The dry run is an eth_call from the owner, so nothing is signed or sent. Send the calldata from your owner wallet to execute.
  • Fork-tested on PulseChain: on an artificially created gap, the contract's profit matched the scanner's prediction exactly for v2→v2 and within 2 wei for a v3 leg. Live routes currently revert with NoProfit, as expected.

New in v4.9.3: ⛽ mainnet-calibrated gas

  • On the first mainnet dry run, a 3-hop V2 route measured 627,914 gas, but the table had estimated 570k (about 9% low). The base cost per route is now 210k instead of 150k, so that route is estimated at 630k. Every "net after gas" figure is now a little more conservative.
  • The dry run's eth_estimateGas is still the number to trust before you send.

New in v4.9.2: ⏱ longer send deadline

  • First mainnet test: the transaction sent from the ZKX wallet reached the ArbExecutor and passed the owner check, but it reverted with Expired() because it was mined about 16.6 minutes after its 120 s deadline. Because it reverted early, it cost only 9.73 PLS in gas.
  • Calldata now gets a deadline of now + 600 s. Dry-run, click Send and approve the wallet pop-up straight away. If the pop-up sat for minutes, reject it and send again. minProfit still protects every trade.

New in v4.9.1: ⛽ realistic gas

  • The old flat gas estimates (250k for 2 hops, 350k for 3) were far too low for ArbExecutor routes. On a fork, a 3-leg route with V3 legs used 770,688 gas. Each route is now estimated as 150k + 140k per V2 hop + 230k per V3 hop, and each row shows its figure, e.g. "(~520k gas)".
  • Dry run now also runs eth_estimateGas for the exact transaction and shows the gas, its PLS/USD cost and, for WPLS routes, net profit after gas. Trust that number over the table estimate.

New in v4.9: 🚀 Deploy kit + 🤖 keeper role

  • Trade Companion → Connect Wallet → Estimate deploy cost (simulation only) and Deploy ArbExecutor. Your wallet signs; the connected account becomes the permanent owner. The page waits for the receipt, checks owner() and remembers the address in this browser.
  • The contract now has an optional keeper: a separate bot key that can call execute() but can never withdraw or change the keeper. Profit always goes to the owner. Set or revoke it with Set / revoke keeper (owner only; empty = revoke).
  • The embedded bytecode is built with pinned settings (solc 0.8.24, evm paris, optimizer 200), the same as contracts/ in the repo. 14/14 fork tests pass, including keeper-can-execute and keeper-cannot-withdraw. The contract is unaudited: start small.

New in v4.8.1: 🔎 Piteas cross-check

  • Trade Companion has an opt-in Check with Piteas button. It asks the Piteas aggregator for the best whole-market price of the route's first hop and the way back (2 requests), then compares that round trip with our route. If Piteas does as well or better, the gap is probably available to everyone.
  • Piteas allows 10 requests per minute and says its API isn't for arb bots, so the button is manual only and capped at 6 requests per minute here. If Piteas is down, the panel says so; the scanner never depends on it.
  • The Tide venue seen in Piteas routes is a Balancer-V3-style weighted pool (5 tokens, 0.30% fee, small balances). It needs different maths and a vault integration, so it is not scanned yet; Piteas hops through Tide are labelled "(not scanned here)".

New in v4.8: adaptive V3 tick depth

  • A V3 tick depth cap slider (1–8, default 4) sets the maximum number of initialized-tick intervals read per direction for each LibertySwap V3 pool.
  • Each pool reads only what your trade size needs: the engine measures the current interval's capacity in start-token units (tighter of both swap directions) and reads size ÷ capacity + 2 intervals, at least 2 and at most the cap. Pools that don't contain the start token (3-hop middle legs) read the full cap.
  • All tick reads stay in the same Multicall3 call pinned to the same block. The telemetry strip shows the depth range used, e.g. "v3 tick depth 2–6 (cap 6)". Raise the cap if big trades show "exceeds safe depth".

New in v4.7: more tokens + 🦊 MetaMask send

Limitations

  • 2-pool cycles and triangular 3-hop routes (S → Y → Z → S over three distinct pools) are checked. The triangular scan applies the 10% reserve cap to v2 legs and the adaptive multi-tick depth (up to the slider cap, 1–8 intervals) to v3 legs, and lists only profitable routes. Gas is estimated per route (live eth_gasPrice × (210k + 140k per V2 hop + 230k per V3 hop), valued at WPLS/USD; calibrated on fork measurements) and the Trade Companion dry run shows the measured eth_estimateGas and shown as net profit; MEV and pending-block state are not modelled. v3 depth is limited to the tick intervals read per direction (adaptive, capped by the V3 tick depth slider). Alerts (🔔 toggle) fire a sound and a browser notification once per newly profitable route, net of gas and above the min-bps filter; they only run while this tab is open, so pair them with Auto-refresh. Bridge checks are non-atomic. The page only sends a transaction when you click Connect & Send and approve it in your own wallet; otherwise it is read-only. MEV and price movement between dry run and execution can still make a transaction revert (gas lost). Verify on-chain before trading.
